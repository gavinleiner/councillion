# One whole operating-system subject

This batch contributes **one question**: name a computer or device operating
system. Its980 canonical answers, source rows, named versions and aliases are
not980 questions. The original66 independently supplied familiar probes remain
unchanged. Actual common public OS families provide easy entry answers; legitimate
historical, research, embedded and distro names remain in the rare tail.
Editorial tiers are familiarity estimates, not measured player frequencies.

## Reproducible factual inputs

`prepare-authored-operating-systems.py` compiles frozen specifications, explicit
role/identity/normalization decisions and source facts. It asserts ownership of
aliases, the original familiar probes, wrong-category boundaries and reviewed
punctuation/case collisions. The canonical source map, held rows and receipts
remain beside the authoring inputs.

The complete captured main sections of
[List of operating systems](https://en.wikipedia.org/wiki/List_of_operating_systems)
and actual distribution-name tables in
[List of Linux distributions](https://en.wikipedia.org/wiki/List_of_Linux_distributions)
were reviewed with their heading/parent/description context. Wikipedia contributors'
material is [CC BY-SA4.0](https://creativecommons.org/licenses/by-sa/4.0/).
Changes include selecting actual named systems, qualifying ambiguous old names,
holding hardware/vendors/environments/source headings, preserving meaningful
version numbers and adding independently proven public names. Country, hardware,
company, API-level, package and source-row fields are not automatically answers.

The source list has904context-bearing main LI leads and266actual distro-table
rows. Those are research inputs, not admissions. Source rows held at this snapshot
include prototypes without implementation proof, hardware wrappers, bare software
frameworks, ordinary GUI/application environments and unverified labels. Actual
named OS children survive held parent hardware headings. Source variants and
repeated tables join only reviewed identities. The source-selection ledger and
108held rows show the decisions; not every source label is declared false.

## Identity and matching boundaries

Actual renamed projects can share an identity. Shared ancestry, a reused acronym,
a similar spelling, shared vendor or hardware do not automatically prove identity.
FreeRTOS/OpenRTOS/SafeRTOS remain different actual products. DatapointCTOS and
ConvergentCTOS are different. IBM/DataGeneralAOS are different. Public version
names remain inside this ONE question.

The existing literal public-name facility now survives the authored metadata
build. Exact public case/punctuation exceptions distinguish iOS/IOS,
Mint/MiNT, RISCOS/RISC/os, EOS and/e/OS, and classic MacOS versus modern macOS.
Canonical display names qualify the otherwise ambiguous rare system. The slash
spelling RISC/os remains case-insensitive; only actual case-dependent names such
as iOS/IOS and Mint/MiNT use literal case distinctions. These
exceptions are explicitly authored names, not generated initials.

This pack also opts into preserving whole numeric tokens in exact matching.
Windows1.0 must not silently become Windows10; Android1.6 must not become
Android16. Explicit dotted public aliases work regardless of letter case, and
a plausible typo still receives a post-submit confirmation. Fabricated Windows9.5
cannot gain Windows95's points by dropping its decimal. Other packs retain their
existing punctuation behavior. No extra suggestions appear while typing.

## Access and coverage limits

All403/429/500/404/timeouts remain recorded. None was evaded or repeatedly retried.
The Windows comparison link redirected to a homepage, so that redirect is not
edition proof. A generic authorization notice appeared alongside publicly indexed
LTSC text; no account access or login was attempted. NIAP returned a JS shell and
an unverified guessed PDF link was inaccessible, so they do not establish the
held XTS400/STOP role. Unverified AnimOS, redacted/proposal labels and ambiguous
bare Quantix remain held pending proper identity/implementation proof.

This is broad factual coverage with explicit boundaries, not a claim to identify
every operating system, patch/build or unpublished hobby project ever made.
No source prose, art, operating-system binary or licensed OS source code is
redistributed as game assets; only factual names and curated identity metadata.
